## Mistakes worth not repeating

| What happened | The lesson |
|---|---|
| Read `ffprobe` saying 1920×1080 and told Edward his clips were landscape. They're 1080×1920 with a rotation flag | Check the decoded frame, not the container metadata |
| Deploy check polled for a string present in *both* old and new builds — passed instantly against a stale cache | Always poll for something only the new build contains |
| Asked which video option he wanted when he'd already said to skip the video | Don't re-open a decision the user has closed |
| Over-explained a paid-generation choice mid-build and derailed the task | Pick the sensible default, say what you picked, keep moving |
| Put a strike-through under "Dream home out" | A line *through* the payoff line reads as crossing it out |

## Quick context for next session

1. Read `CLAUDE.md`, then `docs/open-items.md`. Nothing else until you know your task.
2. Find your task in the routing table. Open the one contract. Load only what its
   Inputs table names.
3. Check any fact against `docs/reference/client-facts.md` before you write it.
   There is a lot on these pages that looks real and isn't.
4. Bump `?v=N` if you touch CSS or JS.
5. Deploy and verify per `docs/tasks/deploy.md` — including the part about
   polling for a genuinely new string.
